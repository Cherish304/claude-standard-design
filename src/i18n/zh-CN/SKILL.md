# project-initial

把文件命名与更新规范框架放进目标目录。框架的文件、模板和脚本都在本 skill 目录内，运行时不需要读取其他位置。

下文的 `<skill>` 指本文件所在的目录。所有路径都相对于它。

## 目录内容

| 路径 | 内容 |
|---|---|
| `SPEC.md` | 规范正文。初始化时复制到目标目录 |
| `VERSION` | 规范版本号 |
| `templates/` | INDEX、实验说明、数据集清单和 Agent 规则块的模板 |
| `tools/init-workspace.sh` | 初始化脚本 |
| `tools/check-workspace.sh` | 一致性检查。加 `--remote` 时核对外部仓库是否有新提交 |
| `tools/pull-external.sh` | 拉取外部仓库的一个版本 |
| `tools/messages.sh` | 工具输出的消息，语言与本 skill 相同 |
| `adapters/<名称>/` | 工具适配层，每个工具一个目录。目前有 `claude-code` |

## 步骤

1. **确定目标目录**。用户给出路径就用它。没有给出，使用当前工作目录，并在回复中写明路径。
2. **查看现状**。运行 `ls -A <目标目录>`。
   - 空目录或新目录：直接初始化。
   - 已有文件：脚本不覆盖已存在的文件。已有 `.gitignore`、指令文件或权限配置时，适配层只提示需要手动补充的规则。已有大量未整理的文件时，不要直接在其上操作，告诉用户按 `SPEC.md` 第 11 节迁移，由用户决定。
   - 目标位于另一个 git 仓库内：脚本不执行 `git init`，属于正常情况，告诉用户即可。
3. **选择适配层**。运行 `ls <skill>/adapters/` 查看可用项。选择与你所在的工具对应的一项，用 `--adapter <名称>` 启用。没有对应项时不加该参数。不加参数时框架照常生成，只缺少该工具的指令文件和权限配置。
4. **运行初始化**：

   ```sh
   sh <skill>/tools/init-workspace.sh [--adapter <名称>] "<目标目录>"
   ```

   目标目录不存在时，脚本会创建它。
5. **核对输出**：
   - `创建:` 是新生成的文件，`已存在，跳过:` 是未改动的文件。
   - 输出中的"手动补充"提示，需要你对照提示里的文件处理。
   - 退出码非 0 时，原样报告错误，不要猜测原因后绕过。
6. **验证**：
   - 目标目录有 `SPEC.md`、`INDEX.md`、`templates/` 和 `tools/`。
   - 初始检查输出 `检查通过`。若有 `[问题]`，逐条说明，不要删除或改写用户文件。
   - 使用了适配层时，检查它写入的文件，说明见 `<skill>/adapters/<名称>/README.md`。
   - 没有使用适配层时，告诉用户：规则块在 `templates/agent-rules.md`，需要放进所用工具的项目指令文件，Agent 才会读取。
7. **告诉用户下一步**，只说这几点：
   - 已有文件要在 `INDEX.md` 登记，或按规范迁移。
   - 拉取外部仓库用 `tools/pull-external.sh`，拉取后把输出的那一行加入 `INDEX.md`。
   - 脚本不提交代码，是否提交由用户决定。

## 不做的事

- 不覆盖已存在的文件，不删除任何文件。
- 不提交、不推送，不拉取远端仓库。拉取需要用户给出地址和分支。
- 不修改 `<skill>` 目录中的文件。
- 不在目标目录之外写文件。

## 版本

`<skill>/VERSION` 是本 skill 自带框架的版本。目标目录 `INDEX.md` 顶部记录初始化时的版本。两者不同时，告诉用户，由用户决定是否手动合并 `SPEC.md` 和模板。初始化脚本不会覆盖已有文件。
